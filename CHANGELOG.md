# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html)
(a site started from it numbers its releases 1, 2, 3; docs/releasing.md).

Each release moves everything under `[Unreleased]` into its own section;
`./tools/release.sh` does it, and `tests/infra/release.test.js` fails until
the version in `VERSION` has one.

## [Unreleased]

### Added
- **CI** (`.github/workflows/ci.yml`, docs/releasing.md): the gate, `./tools/test.sh --coverage`, on every push to `main` and every pull request; read-only, no secrets, actions pinned to commits (`tests/infra/ci.test.js` holds it to that). Porting: the workflow and its test.
- **`parseMedia()`** in `src/core/lib/blocks.js`, exported: checks one image the app describes, such as one a record's own field names (KAW Meetup's event covers), as an image block's is checked, and gives it back. `fetchImage()` now fetches an image shown by two record types once per build. Porting: the two files.
- **Images in pages' blocks** (Waffle's docs/content.md, "Media"): `blocks.js` checks image and gallery blocks and `mediaOf()` lists their images; `Blocks.astro` renders them with Astro's `<Image>` from an `images` map; `fetchImage()` in `src/core/lib/clients/waffle.js` gets each from the app or the fixtures. Brought back from KAW Meetup's site, where the pages loader is the worked example. Porting: the three files.
- **Pages made of blocks** from the app (Waffle's docs/content.md, "Blocks"): `src/core/lib/blocks.js` checks every block, `parseRecords()` takes `body: 'blocks'`, `src/core/components/Blocks.astro` renders them as plain semantic HTML, and `src/core/lib/routes.js` fails the build when an app page's slug is one of the site's own. Brought back from KAW Meetup's site. Porting: copy the three files and `Blocks.astro`, and `records.js`.
- **The template**: an SEO-first marketing site and blog that fronts a [Waffle](https://github.com/treehousetim/waffle) app, built the same way: a fixed stack, a test-first method, guard rails that fail the build, and a one-server deploy by GitHub Actions.
- **Static pages from Astro 7.** Pages are `.astro` files written by hand or by an agent from a shared component library; blog posts are Markdown with a strictly checked schema. Production serves plain files, with no application server.
- **An SEO audit on the built HTML** (`tools/audit.mjs`, rules in `src/core/lib/audit.js`): one `<h1>`, unique titles and descriptions, canonical and Open Graph tags, alt text, working internal links, valid JSON-LD, nothing the content security policy would block, robots and sitemap that agree with the build. Errors fail the build, the release and the deploy.
- **Local business structured data**: `Electrician` (any LocalBusiness type) with address, hours, phone and the towns served on every page; `Service`, `FAQPage`, `BlogPosting` and breadcrumbs where they belong.
- **The waffle app, at build time and at run time** (docs/waffle-api.md): pages read `/api/site/*` while the site builds (fixtures in development and tests), and Caddy forwards `/api/site/*` from the browser to the app with a site key, stripping the visitor's cookies.
- **Preview builds can never be indexed**: anything but a production build is `noindex, nofollow` everywhere with a `Disallow: /` robots.txt, and the audit checks both.
- **Atomic releases with instant rollback**: every release lands in `releases/vN/` and `current` is switched by a rename; `deploy.sh` proves the new home page is being served over HTTPS, and switches back if it is not.
- **The example site**: a local electrician with 8 service pages, 6 town pages, a price guide from the API, reviews, an emergency page, an FAQ, a quote form and a 24-article blog.
- **Supply chain defences carried over from Waffle**: npm only through `tools/npm.sh`, in a container, install scripts off, nothing younger than a week; `npm audit signatures` in CI.
- **A design pass on the example site** (docs/design.md): a self-hosted Inter typeface, a token-based design system, photo-led heroes and cards, a sticky header with the phone number and a working desktop navigation, a fixed call / quote bar on phones, sticky quote cards on service and town pages, an emergency band, image-led blog cards with a featured post, related posts and a help box on every article, styled FAQ, prices and form. Twenty-four free Unsplash photographs (credited on `/credits/`) through one `Photo` component that resizes, converts and sizes every image.
- **Example sites, and a shared core** (docs/examples.md): the template now holds complete example sites in `examples/<name>/`, each with its own design, playbook and end-to-end checks, over a small shared core in `src/core/` (settings, the waffle client, SEO and structured data, the audit, the `<head>`). `SITE_EXAMPLE` picks one to work on; setup installs the chosen one as the site's own code (`tools/use-example.sh`) and removes the rest. Every example is built, audited and checked on every change.
- **Eight more example sites**, each its own design, logo, motion, photographs, blog, waffle data and form: mobile auto detailing, a wedding photographer, a dental practice, a bakery, a yoga studio, a brewery, a veterinary clinic and a law firm. Twelve more are designed and recorded in docs/examples.md, not built.
- **Done the Astro way**: Astro's own content security policy (hashes for every script and style, in each page), its Fonts API (self-hosted, preloaded), `<Picture>` with AVIF and WebP, `astro:env` for the build settings, prefetching, SVG icons as components, robots.txt as an injected route.
- **Motion**: page changes cross-fade with the browser's own view transitions; heroes rise in, bands and cards rise into view on scroll, the header lifts and articles show reading progress, all CSS (scroll-driven animations), all switched off for reduced motion.
- **A site made from the template passes its own tests**: the setup scripts' tests, which need the template's examples and placeholders, are removed by setup and stay with the template; tests no longer write the placeholder hostname in a form the rename cannot reach, and a structure test keeps it that way. Found by the first real site, KAW Meetup.
- **The Compose project is named for the slug** (`name:` in `docker-compose.yml`), whatever folder the site is cloned into.
- **Scoped rebuilds from data** (docs/scoped-builds.md), proven first on KAW Meetup's event pages. Core: `records.js` (the waffle app's records with slugs, fingerprinted), `manifest.js` (the page manifest, the affected pages before and after, what a scoped release copies and removes), `redirects.js` (a Caddy snippet of 301s for old slugs and 410s for retired ones), `sitemap.js` (a scoped release's sitemap). `rebuild.yml` turns a `change-notice` repository_dispatch into a build of the served release's code against the served manifest; `tools/scoped-release.mjs` picks what changed; `deploy/assemble.sh` lays it over a hard-linked copy of the served release and deploys it as `v<N>.d<run>`, which `deploy.sh` now accepts. The Caddyfile imports `redirects*.caddy` from the release being served; `deploy.yml` passes `SITE_RELEASE`. Porting: copy those files and the tests beside them, the Caddyfile `import` line, the `SITE_RELEASE` and `SITE_PREVIOUS_MANIFEST` env fields in `astro.config.mjs`, the tag pattern in `deploy.sh`, and `SITE_RELEASE` in `deploy.yml`'s build step; then write the site's own `pages-manifest.json` and `redirects.caddy` endpoints (docs/scoped-builds.md, "What a site writes").
- **Tests**: `./tools/test.sh`, Node's test runner in a container; `src/core/lib` at 100% line, branch and function coverage; infra tests for every script, the Caddyfile and the workflow; an end-to-end test that builds the site twice and leaves a repeatable artifact.

### Fixed
- **An image's credit shows without a caption**, and a gallery names whose its images are (`src/core/components/Caption.astro`, from `creditsOf()` in `src/core/lib/blocks.js`), each credit linked when the app has a link; a credit link that is not https:// fails the build. Before, a licensed image with no caption was shown with no credit, which its licence does not allow. Found in KAW Meetup's site. Porting: `blocks.js`, `Blocks.astro` and `Caption.astro`.

### Security
- **HTML rendered from the app's Markdown is sanitised** with `sanitize()` (`src/core/lib/sanitize.js`): Astro's Markdown renderer passes raw HTML through, so a loader that renders the app's Markdown passes the HTML through `sanitize()`, which keeps only the tags Markdown makes, the attributes they need, and links to site paths, anchors, https and mailto. The app refuses raw HTML too; this is the second line. Porting: copy `sanitize.js` and its test; call it on every `renderMarkdown()` result built from the app's data.
- **The visitor's address goes to the app as `X-Visitor-Address`** (`header_up X-Visitor-Address {client_ip}` in the Caddyfile), which Waffle's form rate limit reads; the app's own Caddy rewrites `X-Forwarded-For` to this server's address, so every visitor shared one limit. Porting: the one Caddyfile line; the app side is Waffle's.
- **An app page's old or retired slug never redirects or 410s one of the site's own pages**: `withoutOwn()` in `src/core/lib/routes.js`, for the redirects a site writes from its data. Porting: filter previous and retired page slugs through it in your `redirects.caddy.ts`.
- **npm never shares a job with the deploy secrets.** `deploy.yml` and `rebuild.yml` build in a job with no environment and hand the result, as an artifact, to a ship job that runs no npm: a process an npm package starts cannot outlive its job, so it cannot read the server's key (loading secrets later in the same job was not enough). A failed build or ship is reported by its own `alert` job. Rebuilds ship through a new `prod-rebuild` environment, deployable from the default branch only (a change notice's dispatch runs there), which `tools/setup-github.sh` now creates with its own read-only Doppler token; every job also carries the template's own repository guard. Porting: replace both workflows and `tools/setup-github.sh`, then run `./tools/setup-github.sh` once to add `prod-rebuild`.
